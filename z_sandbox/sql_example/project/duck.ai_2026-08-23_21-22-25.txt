```python
import sqlite3
from flask import Flask, render_template

app = Flask(__name__)

def get_db_connection():
    connection = sqlite3.connect("database.db")
    connection.row_factory = sqlite3.Row
    return connection

@app.route("/")
def index():
    connection = get_db_connection()
    results = connection.execute("""
        SELECT Pk_ID, date, opponent, surface, playStyle,
               win, green, red, rate

        ORDER BY Pk_ID
    """).fetchall()
    connection.close()

    return render_template("results.html", results=results)
```

That warning means Flask’s built-in server is intended for local development only. It is convenient, but it is not designed to handle production traffic, provide strong security defaults, or manage multiple worker processes.

A simple production setup is:

```text
Internet
   ↓
Nginx or another reverse proxy
   ↓
Gunicorn
   ↓
Flask application
   ↓
SQLite database
```

## 1. Prepare your Flask application

Assume your project looks like this:

```text
myapp/
├── app.py
├── database.db
├── templates/
│   └── results.html
└── requirements.txt
```

Your `app.py` should expose a Flask object named `app`:

```python
from flask import Flask, render_template
import sqlite3

app = Flask(__name__)

def get_db_connection():
    connection = sqlite3.connect("database.db")
    connection.row_factory = sqlite3.Row
    return connection

@app.route("/")
def index():
    connection = get_db_connection()
    results = connection.execute("""
        SELECT Pk_ID, date, opponent, surface, playStyle,
               win, green, red, rate
        FROM results
        ORDER BY Pk_ID
    """).fetchall()
    connection.close()

    return render_template("results.html", results=results)
```

Create a dependency file:

```text
Flask
gunicorn
```

Then install the dependencies:

```bash
pip install -r requirements.txt
```

## 2. Test with Gunicorn

From the project directory, run:

```bash
gunicorn --bind 127.0.0.1:8000 app:app
```

The syntax is:

```text
gunicorn module_name:flask_variable
```

So:

```text
app:app
```

means:

- `app.py` is the module
- `app` is the Flask application object

You can then visit:

```text
http://127.0.0.1:8000
```

For a small application, this may be enough if another service or hosting platform handles HTTPS and external access.

You can use multiple workers:

```bash
gunicorn --workers 2 --bind 127.0.0.1:8000 app:app
```

For SQLite, avoid using too many workers. SQLite is suitable for small applications and mostly read-oriented workloads, but it allows limited concurrent writing.

## 3. Use a reverse proxy

For a typical Linux server, Nginx can receive public HTTP/HTTPS requests and forward them to Gunicorn.

A basic Nginx configuration might look like:

```nginx
server {
    listen 80;
    server_name example.com;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

Nginx provides a useful front layer for:

- HTTPS termination
- Static files
- Request buffering
- Connection handling
- Reverse proxying
- Basic access controls

You would normally configure HTTPS with a certificate, commonly through Let’s Encrypt and Certbot.

## 4. Run Gunicorn as a service

Rather than starting Gunicorn manually, use `systemd` so it starts automatically and restarts if it crashes.

Example service file:

```ini
[Unit]
Description=Gunicorn service for Flask application
After=network.target

[Service]
User=www-data
Group=www-data
WorkingDirectory=/var/www/myapp
Environment="PATH=/var/www/myapp/venv/bin"
ExecStart=/var/www/myapp/venv/bin/gunicorn \
          --workers 2 \
          --bind 127.0.0.1:8000 \
          app:app
Restart=always

[Install]
WantedBy=multi-user.target
```

Save it as:

```text
/etc/systemd/system/myapp.service
```

Then run:

```bash
sudo systemctl daemon-reload
sudo systemctl enable myapp
sudo systemctl start myapp
```

Check its status:

```bash
sudo systemctl status myapp
```

View application logs:

```bash
sudo journalctl -u myapp -f
```

## 5. Protect the SQLite database

Make sure the application user can read and write the database:

```bash
sudo chown www-data:www-data /var/www/myapp/database.db
sudo chmod 640 /var/www/myapp/database.db
```

SQLite also creates a journal or WAL file during writes, so the directory containing the database must usually be writable too:

```bash
sudo chown -R www-data:www-data /var/www/myapp
```

Do not place the database inside a publicly served static directory.

Back it up regularly:

```bash
sqlite3 database.db ".backup 'backup.db'"
```

For production applications with frequent writes, multiple users, or larger datasets, consider migrating to PostgreSQL.

## 6. Set production configuration

Do not run Flask in debug mode:

```python
app.run(debug=False)
```

With Gunicorn, you do not need `app.run()` at all for deployment.

Keep secrets outside your source code. For example:

```python
import os

app.secret_key = os.environ["SECRET_KEY"]
```

Set the environment variable on the server:

```bash
export SECRET_KEY="a-long-random-secret-value"
```

You should also:

- Keep the database outside public directories.
- Use HTTPS.
- Validate and authorize data-changing requests.
- Add CSRF protection if you introduce forms.
- Avoid displaying raw exception details to visitors.
- Keep dependencies updated.
- Configure backups and logging.

## The simplest practical deployment

For a small Flask application, the next step is usually:

```bash
pip install gunicorn
gunicorn --workers 2 --bind 127.0.0.1:8000 app:app
```

Then place Nginx or your hosting provider’s HTTPS proxy in front of Gunicorn. The Flask development server is replaced by Gunicorn, while your application code and templates can remain largely unchanged.
